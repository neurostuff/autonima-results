# Run tiers and what differs between them

Generated by `scripts/compile_tier_specs.py`. Every difference below is computed from the configs themselves, not from their headers.

## The tiers

| tier | definition |
|---|---|
| `initial` | Criteria transcribed from the source paper before any results were seen. An LLM or a human helping to DRAFT from the paper does not disqualify a run here; being revised against error reports does. |
| `manual` | The highest version whose criteria the author revised BY HAND, having inspected a few report examples. Light peeking. |
| `untuned` | The highest version whose criteria were NEVER iterated against this project's benchmark error reports. Permits LLM-authored criteria and LLM- or gold-tuned SEARCH; forbids criteria edited after seeing which studies or analyses the pipeline got wrong. Not a synonym for `manual`: it is set for five projects whose `manual` is empty, and for social it is HIGHER than `manual`. |
| `best` | The curated preferred run. Benchmark-informed tuning fully allowed. Selected on recall rather than F1 for canonical runs, because with a mixed pool a false positive may be a good paper the source meta-analysis never screened. |
| `latest` | Highest version number, mechanically. Kept as a sanity check. |

`untuned` is the tier to cite for any claim that a result was not fitted to the benchmark. Where a family has no such run the registry says `untuned: null` explicitly; callers must skip those rather than auto-picking, which would silently substitute the tuned run.
