## Results

A general-purpose agent with workflow skills approaches but does not exceed the dedicated harness

To test whether AutoNIMA's dedicated harness is needed, or whether a general-purpose coding agent can reproduce the workflow from written instructions alone, we packaged the same stages as agent skills and ran them on all nine projects (Methods). In this configuration an orchestrating agent ran search, screening, coordinate extraction, analysis selection and meta-analysis, delegating each judgment to a judge model. It received the same eligibility criteria, search queries and date limits as AutoNIMA, but none of its prompt construction, structured-output handling, retry logic or caching. We evaluated three orchestrator–judge pairings: two in Codex (Sol with Luna 5.6 judges, and Astra for both roles) and one in Claude Code (Claude Opus 5.5 with Claude Haiku judges).

All three agent arms reached accuracy close to AutoNIMA's, with no consistent advantage (Fig. S6). Mean screening F1 was 0.449, 0.464 and 0.424 for the Sol–Luna, Astra and Opus–Haiku arms, against 0.437 for AutoNIMA (Wilcoxon signed-rank P ≥ 0.25 across nine projects for each arm). Final recall was lower in every agent arm (0.64 to 0.67, against 0.73), whereas precision ranged from 0.32 to 0.38, against 0.32 for AutoNIMA. Spatial correspondence with reference maps was slightly lower for all three (mean r², 0.506, 0.526 and 0.481, against 0.524 for AutoNIMA, across 31 to 32 target contrasts), although no difference reached significance (Wilcoxon P ≥ 0.16). The agent maps exceeded AutoNIMA in 8 to 13 contrasts. Opus–Haiku, the lowest-scoring arm, fell furthest behind on dementia and social cognition, where its project-level r² fell by 0.10 and 0.11 respectively.

Comparable accuracy came at higher cost and with less predictable execution. The Opus–Haiku arm, the only one with recorded token use, cost about US$100 per project (US$899 across nine projects), roughly five times AutoNIMA's US$21.55 (Fig. S5). Most of the excess came from analysis selection, where repeated attempts and longer responses used 2.3 times the tokens that AutoNIMA used. Although every run was instructed to proceed end to end, the orchestrator paused for operator decisions one to four times per project in the Opus–Haiku arm. These decisions included whether to accept quotations that could not be found in the source text, whether to raise retry limits and whether to skip targets with few studies. Some of these choices alter which studies enter a map. The Codex arms rarely paused, but they applied unrequested defaults at the fitting step, such as omitting analyses with unreported coordinate spaces or overlapping samples. These defaults had to be identified and reverted before the arms could be compared. A dedicated harness fixes these decisions in a versioned configuration before execution. A general-purpose agent can reproduce the workflow's accuracy, but it does not provide this guarantee without additional controls.

## Methods

Skills-based agent comparison

The skills-based arms used a package of agent skills that described each workflow stage in natural language, together with small generic helpers: a PubMed E-utilities client, a full-text normalizer and NiMARE. A ledger script recorded every judge decision and served as the only writer of decision files. It also checked criterion identifiers and verified that quoted evidence appeared in the source text. Judges answered without tool access, returning structured responses that the ledger validated. Each project's criteria were translated one-for-one from the corresponding AutoNIMA configuration, and gold-standard files were kept outside the agent's workspace. Coordinate extraction used the full article text, including tables. Meta-analyses used the same MKDA settings as AutoNIMA. Analyses whose coordinate space was not reported were treated as MNI, matching NiMARE's default. For the Codex arms, which had omitted such analyses and overlapping samples during fitting, maps were refitted from the recorded selections under the same rule. Screening and map correspondence were scored against NeuroMetaBench with the same procedures used for AutoNIMA. Opus–Haiku costs were calculated from recorded token use at the Claude list prices (Claude Haiku: US$1 per million input tokens, US$0.10 per million cached-input tokens, US$5 per million output tokens; Claude Opus 5.5: US$4, US$0.20 and US$20 respectively). Token use was not recorded for the Codex arms.

## Fig. S6 caption

Skills-based agent workflows compared with AutoNIMA. Screening F1 for final inclusions (left) and mean correspondence with reference maps (right; Pearson r between unthresholded z maps, averaged over each project's target contrasts) for three orchestrator–judge pairings running the workflow as agent skills: Sol with Luna 5.6 judges and Astra in both roles (Codex), and Claude Opus 5.5 with Claude Haiku judges (Claude Code). Vertical grey marks show AutoNIMA on the same project. All arms received the same eligibility criteria, searches and MKDA settings. Analyses with unreported coordinate space were fitted as MNI in every arm. Mean screening F1 was 0.449, 0.464 and 0.424 for the three agent arms and 0.437 for AutoNIMA. Mean map correlation was 0.687, 0.711 and 0.676, compared with 0.706. No arm differed significantly from AutoNIMA on either measure (Wilcoxon signed-rank test across nine projects, P ≥ 0.16).
